01 / CORRECTION

Laya、JEV 没拼错：它们改变了“拼智能”的基本单位

上一版把二者误判为语音转写错误，这是错误的。Laya 是可本地部署的开源 System One 决策模型；JEV 是 TypeSafe AI 的闭源 API。它们都不是逐 token 生成文本，而是针对给定 state，一次前向输出类型化决策与置信度。

上一版错误前提

把“小设备拼智能”等同于“把一个 LLM 切到很多设备”，因此只比较了 pipeline、tensor parallel 与多 Agent。

更新后的问题

把智能拆成 state 表征 → typed decision → planning → tool use → expression。其中高频判断可交给 421M 级决策模型并行处理；LLM 只承担开放式推理与表达。

证据边界：Laya 官方仓库为本轮直接读取；JEV、Ollama/llama.cpp 生态及大部分 2026 项目数据来自搜索索引抓取。页面将这两类证据分开，不把 index 结果写成实测。
02 / SYSTEM ONE

决策模型不是“小一点的聊天模型”

它不生成一段推理文本，而是对 Choice / Score / Noul 等 typed question 给出答案与经过标定的概率。对多设备系统而言，这意味着最合理的扩展方式是复制、分工、集成，而不是切分 843MB 权重。

04 / CPU BENCHMARKS

一个 CPU 能跑，但“跑起来”与“可交互”差一整个档位

以下均是单机 CPU 路径；NPU、Metal 与 WebGPU 数据只在注明时作为对照。速度统一看 autoregressive decode，而不是通常快 5–30 倍的 prefill。这里把 ≥10 tok/s 作为可交互参考线，不把低速出 token 误写成体验可用。

LOADABLE · 能加载

先过内存门槛

经验下限是内存至少为 Q4 权重体积的 1.5 倍。Pi 5 8GB 可把 8–9B Q4 跑到约 1–2 tok/s，但这只是“能出 token”。Pi 5 汇总 ↗

INTERACTIVE · ≥10 tok/s

再过解码门槛

Pi 5 的现实上限约在 ≤1B；1.7B–4B 通常要旗舰手机 SoC 或桌面 x86。4GB Amlogic S905 盒子只有“≤1.5B Q4 可能装得下、约 4–8 tok/s”的带宽推算，没有公开整机实测。

A / DECISION SWARM

决策模型群

软件可用 · 盒群待测

目标形态是每台设备完整运行 Laya，按 schema、问题集或 checkpoint 分工；用 calibrated confidence 做加权集成与升级门控。同模型复制投票的误差高度相关，异构 checkpoint / 温度 / schema 才更可能有收益。

拼法
复制 + 分工，不切分；coordinator 调多个 /v1/systemone 服务。
独特价值

B / MODEL SHARDING

大模型分片

已可用*

Anthropic 基线是 15 台 $55 盒子 pipeline 跑 Gemma4-26B-A4B，0.39 tok/s。llama.cpp RPC 可手动组网；distributed-llama 则证明 tensor parallel 在 Pi 5 LAN 上可行。星号代表“能跑”，不是“自动弹性成熟”。

实证
4×Pi 5：Llama 3 8B 从 1.77→3.01 t/s；另一份 2026 报告的 Qwen3-30B-A3B 为 15.143 tok/s。

C / HIERARCHICAL AGENTS

分层智能体

协议已可用

较强 coordinator 规划，盒子 worker 运行小 LLM 或决策服务；A2A 做发现和委派，MCP 暴露工具。它是最自然的任务级弹性：worker 失联只需重派任务。

现成部件
A2A v1.0 与 MCP 已就绪，但没有“机顶盒多智能体”的 turnkey 框架。
成本
研究索引报告 multi-agent 约 15× token 成本，不能把并行误写成免费。
头号瓶颈
coordinator 上下文、坏计划级联、跨设备任务状态机。
A2A ↗MCP / A2A ↗
D / SPECULATION & CASCADE

推测解码与级联

跨设备可原型

端侧小模型起草、较强模型验证；或小模型先答、低置信时升级。单机推测解码已成熟，但跨设备还需要处理拒绝后的 KV 回滚与重同步。

证据
AceSpec 讨论 50 Kbps WAN edge-cloud；SwarmLLM 用 speculative chains 摊销 per-hop 成本。
关闭条件
索引中的生产规则建议 acceptance <45% 自动关闭；不是普适定律。
头号瓶颈
acceptance 不可预测，以及 rejection 后分布式状态修复。
AceSpec 综述 ↗SwarmLLM ↗
E / EXPERT PARALLEL

MoE 专家并行

跨弱设备无路径

vLLM Elastic EP 可运行时增删 worker、重分布 experts，但 worker 是 CUDA / HIP GPU 进程，依赖 NCCL / NIXL。它解决数据中心 GPU，不等于能下沉到机顶盒。

现实替代
弱设备今天更适合单机 expert offload，或用 TP 切每个 expert，而不是 per-token 跨机 all-to-all。
证据边界
EdgeMoE / Edge0 / BigMoMo 支撑的是端侧 offload；没有公开跨弱设备 EP 实现。
头号瓶颈
每层两次 all-to-all、EPLB 与异构 straggler；缺 CPU/弱设备通信后端。
vLLM Elastic EP ↗EdgeMoE ↗
F / TRAINING

分布式训练与 RLCD

RLCD 可原型

LLM 级 RL 在 0.39 tok/s 盒子上不现实；但 Laya 类非自回归决策模型每次 rollout 只需一次前向，因此“弱设备收集 rollout + 中心更新”值得验证。

部件
laya-rs 已有 RLCD 循环；Flower 支持 Android / Pi / Jetson 真机客户端；没有端到端整机方案。
参照
INTELLECT-2 证明全球分布式 32B RL 可行，但 rollout worker 门槛是 4×RTX 3090 级。
头号瓶颈
奖励与决策日志设计、RL 稳定性及梯度同步，而非仅网络。
laya-rs ↗INTELLECT-2 ↗Flower semi-async ↗
G / WORLD MODELS

JEPA / 世界模型 + 决策头

组合可原型

JEPA 与 JEV 名字相近但无关。JEPA 负责状态表征与未来预测；System One 负责给定 state 的 typed judgment；LLM 负责开放推理、规划与表达。三者互补，不是替代关系。

公开近似
V-JEPA encoder → 融合 → 轻量 action head → OOD / confidence gate → ONNX / CoreML。
边界
公开旁证主要是视觉 / 机器人与 MacBook demo，不是文本 agent 或机顶盒实测。
头号瓶颈
缺少“预测—决策”闭环现成栈，需要自行训练 encoder 与 typed head 的对齐。
JEV ≠ JEPA ↗V-JEPA 路线 ↗

07 / INVEST

2026 年底，工程资源只押两条

目标是“一堆机顶盒拼出有用的智能体”，不是证明分布式计算存在。排序因此以交互价值、容错边界和可迭代性为先。

#1 · PRIMARY

A + C：决策模型群 + 分层智能体

先在 x86 / Mac 复现 Laya 服务，再选一台目标盒验证；通过后才扩成每盒一个 laya-serve 或 Ollama /v1/systemone worker。较强 coordinator 负责 state、规划、MCP 工具和表达。

  1. 按问题集、checkpoint 或场景分工，不切权重。
  2. 置信度三档门控：自动执行 / 二次验证 / 升级 LLM 或人工。
  3. 设备掉线只损失一个 worker，任务可重派，不迁移共享 KV。
  4. 最先验证：ARM 盒子实测、分布外 calibration、state 构建质量。
#2 · BACKGROUND

B：pipeline / TP 大模型

只服务于必须保留“一个大模型”且允许低速的后台任务。复刻 Anthropic 15 盒 pipeline，或以 distributed-llama 的 Pi 5 tensor parallel 为性能参照。

  1. 先固定同构硬件与模型分片，不从任意异构设备热加入开始。
  2. 用外部 coordinator 做发现、健康检查、整链重启；不要把 llama.cpp RPC 当安全生产服务。
  3. Petals 可研究其 DHT 思路，但不依赖公共 swarm。
  4. 最先验证：掉线恢复时间、KV 重建成本、持续吞吐与功耗。
暂不投：vLLM EP 下沉缺弱设备后端，不是工程量堆出来就能补齐。
暂不投：盒群 LLM RLrollout 吞吐不成立；把实验转向 RLCD 决策模型。
暂不依赖：Petals 公共 swarm2026-09 死亡实测，私有 swarm 也未在本轮验证。
