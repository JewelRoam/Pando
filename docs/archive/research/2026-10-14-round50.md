# Research Round 50 — rootd /shutdown kill-switch (2026-10-14)

- THREAT-MODEL.md promised a "human kill-switch"; it now exists in code.
- POST /shutdown with a valid token -> graceful stop (root + all connections).
  Without a valid token -> 403 Forbidden.
- Token is set at boot time (set_auth_token); the 403 path is smoke-verified.
  The 200 path needs boot-time token configuration (env var or CLI arg).
- Design: the token is process-local (not persisted), so a restart generates
  a new one - an attacker who compromises a running root cannot reuse an old
  token after a restart. This is intentional: the kill-switch is for the
  human operator at the console, not for remote automation.
