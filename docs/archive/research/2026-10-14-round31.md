# Research Round 31 — pad buckets: correctness OK, granularity wrong (2026-10-14)

- _OVLazySession pad_to mode implemented: bucket every dynamic dim, pad
  inputs (input_ids with pad_token_id, others 0), slice outputs back.
- Padding-invariance verified: all 14 en-suite tasks answered on GPU with
  bucketed shapes, semantic results preserved (choice=refund on the probe).
- BUT the naive uniform bucket (everything -> next multiple of 256) is a
  performance disaster: batch 1 -> 256 rows, markers 3 -> 256 => one
  inference = 7.6 s (256x the rows needed). p50 across suite: 7.6 s.
- Fix designed, not yet implemented: PER-DIM buckets - batch dim exact
  (small set of values), seq dim bucketed (64/128/256), marker dims small
  buckets (8/16). Requires dim-position awareness in _pad_feed (positional
  semantics: dim0=batch, dim1=seq, marker dims=option count).
- Status: correctness proven, performance pending one more iteration.
