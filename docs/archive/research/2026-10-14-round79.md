# Research Round 79 — Expanded prompt pool and CUDA v7

Date: 2026-10-14

## Expanded data

`tools/build_prompt_pool.py` generated 78 multi-lingual prompts across
refund, security, operations, moderation, and support domains. The six
manually labeled holdout states have zero overlap with this pool.

The real English/multilingual/typed-decision HTTP swarm answered all 78
prompts:

```text

cross-lineage splits:   59
split rate:             75.64%
exported contrast rows: 45
```

## Held-out result

The separate six-task heldout remained untouched:

```text
accuracy:             0.6667 -> 0.6667
labels:               6/6 unchanged
max confidence delta: 0.2007
```

The worst case remained the same wrong held-out answer:

```text
ml12b expected complaint, predicted refund
confidence: 0.9716 -> 0.9992
```

More contrast data slightly reduced confidence drift versus v6 (0.2007 vs
0.2649), but did not fix the wrong answer or improve held-out accuracy.

## Calibration

Four calibration items were available, still below the trainer's minimum
of ten:

```text
choice: not fitted: 4 calibration items, fewer than 10
```

The in-sample calibration slice improved:

```text
ECE:             0.3171 -> 0.1950
mean confidence: 0.6829 -> 0.8050
```

This is directionally useful but not a held-out calibration claim.

## Interpretation

Scaling from 18 to 41 train items preserved all six held-out labels and
reduced confidence inflation relative to the four-epoch small-data run.
It still did not create a new correct decision boundary. v7 is therefore a
useful candidate artifact, not yet a replacement lineage.

## Next requirement

The next step is not more prompts from the same generator. It is a larger
independent prompt source with:

- new semantic families rather than template variations;
- at least ten calibration items;
- a frozen heldout set large enough to measure label changes;
- A/B placement of old and new lineages in the live root.
