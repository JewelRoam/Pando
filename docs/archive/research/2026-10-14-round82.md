# Research Round 82 — Spore generation and parent provenance

Date: 2026-10-14

## Change

Spore manifests now carry a monotonic reproduction generation and a direct
parent-manifest hash:

```text
generation = parent generation + 1
parent_manifest_hash = sha256(unsigned parent manifest)
```

`pandosi.spore.validate_reproduction()` rejects:

- generation gaps or rewinds;
- a child whose parent hash does not match the supplied parent.

Each receiving node also appends a local lineage record containing its
manifest hash, parent hash, generation, and lineage name.

## Three-hop result

```text
origin -> B -> C -> D
generation: 0 -> 1 -> 2
chunks: 97
integrity failures: 0
```

Every hop remained byte-identical to the origin. A forged child with an
incorrect parent hash was rejected.

## Why this matters

Unbounded reproduction needs more than transferring bytes. It needs a
verifiable answer to:

```text
which manifest produced this child?
```

The new linkage makes lineage rollback, mislabeled generation, and direct
parent substitution detectable before a child is accepted.

`join --spore` now reports the generation it pulled and appends the event to
`spore-cache/<node>/lineage.jsonl`.

## Limitations

- The current chain still uses one signing key for all nodes.
- Parent validation requires the parent manifest; a node that only receives
  a child can record provenance but cannot prove the parent exists locally.
- There is no global generation policy or fork-resolution rule yet.

These are the next pieces needed for a multi-parent reproduction DAG.
