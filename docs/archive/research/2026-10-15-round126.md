# Research Round 126 — The cheap independent member, shipped

Date: 2026-10-15

## What the last four rounds left to do

Rounds 122-125 established the swarm's economics by measurement: it buys
error independence rather than accuracy, a member is worth several points at
57.5% accuracy when its mistakes do not co-occur with the others', and
nothing derived from the neural family supplies that - a fine-tuned
descendant and a reversed ballot agreed on 100% of answers, a quantised
sibling on 80%, all with positive error correlation.

What was missing was a member. Every round so far measured a voter that
existed only inside an analysis script. This round makes the one that paid
into a first-class citizen of the system, and measures it on the live path.

## The member

`pandosi/textmodel.py` is a multinomial naive Bayes over word tokens and
adjacent pairs, standard library only, with the same `decide(request)`
contract as the neural backends. `stemd --backend text --text-model <path>`
serves it like any other stem, so a device that cannot hold a 1.6 GB graph
can still contribute a vote.

`tools/train_text_model.py` fits it and, because the project's rule is that
a vote on an unknown confidence scale cannot justify an autonomous action,
fits its temperature on rows the counts did not see and writes the same
`assets/calibration/<checkpoint>.json` every neural lineage has:

| | |
|---|---|
| trained on | 192 dev rows |
| features | 630 |
| artifact size | **19 KB** |
| dev holdout (48 rows) | 87.50% |
| fitted temperature | 0.80 |

The 19 KB is the point of the exercise, and so is the 57.5% this model scores
on wording it has not seen (round 123 measured the same approach). It is not
a good model. It is a *different* one.

## The measurement, over the wire

`tools/hetero_swarm_check.py` starts two roots on loopback over the same four
real HTTP stems - three neural lineages, and those three plus the text
member - and asks both the same questions from the wording-held-out split.
The comparison is paired: same stems, same tasks, and the only difference is
whether the fourth vote exists.

240 held-out tasks, scored on the wording-held-out split:

| | full coverage | auto-accepted | accuracy where auto |
|---|---:|---:|---:|
| three neural lineages | **73.75%** | 172 | 90.12% |
| plus the text member | 72.92% | 154 | 90.91% |
| matched at the trio's 172 rows | 90.12% | | 89.53% |

The member made the swarm **worse**. Round 123's offline prediction - the
same model, the same split, +3.8 points at full coverage - did not survive
contact with the live gate, and the reason is not the member.

## The offline prediction used a different rule

Round 123 ranked the quorum by the confidence-weighted vote (`margin`).
The shipped gate counts votes and, when the count ties, returns no choice at
all. Three members cannot tie. **Four can**, and the text member - at 57.5%
accuracy and genuinely independent - turns some 2-1 disagreements into 2-2
splits. Under the gate each of those becomes a non-decision: accepted
coverage fell from 172 rows to 154, and at full coverage a 2-2 row counts as
wrong, so the information the new member brought was discarded rather than
weighed.

Replaying the recorded live votes offline reproduces the live numbers
exactly (73.75%/172/90.12% and 72.92%/154/90.91%), which is what makes the
diagnosis testable: `tools/tie_break_check.py` shows that breaking a tied
count by confidence mass - still at the `verify` tier, so a tied quorum can
never act alone - takes the four-member swarm to **78.33%** at full coverage
and answers all 240 rows instead of 213.

That fix is round 127.

## A failure mode this round found

The first full run reported **1.67% accuracy** and took eighteen seconds. The
swarm was fine; the harness was not. `HEARTBEAT_TTL` is 15 seconds, and a
stem that registers once and then goes quiet is dropped from `live_nodes`.
After the TTL every decision in the run had an *empty quorum*, escalated, and
returned no choice - and the response looked as complete as a real one,
because a quorum of zero reports `responded == quorum_size` exactly as a
quorum of three does.

Production is not affected: `stemd --root` runs `heartbeat_loop`, which is
what keeps a stem in the registry. A check that registers directly is not,
and the second run was measured with the production heartbeat path.

Two things are worth carrying forward from this:

- a check harness must heartbeat, or it measures the TTL;
- the *response* should make an empty quorum unmistakable. `tier=escalate`
  with `quorum_size: 0` is honest but easy to average over, and a monitoring
  rule that treats "escalate" as a policy outcome will not notice that the
  swarm stopped answering.
