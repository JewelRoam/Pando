# Research Round 74 — Real lineage identity over HTTP

Date: 2026-10-14

## Problem found

`OnnxLayaBackend` previously derived its checkpoint identity only from the
device:

```text
CPU -> onnx
GPU -> onnx-gpu
NPU -> onnx-npu
```

That erased the actual Laya lineage. Three different ONNX graphs could
appear to the root as one checkpoint family, defeating checkpoint-diversity
selection in the real serving path.

## Fix

`OnnxLayaBackend` now accepts an explicit checkpoint identity.

`stemd` forwards its `--checkpoint` value to the ONNX backend, and `join`
supports the same override for local ONNX stems. Device-derived names remain
the default only when no lineage is supplied.

## Real HTTP experiment

Three real CPU ONNX stems were started with explicit identities:

| lineage | checkpoint |
|---|---|
| `convaiinnovations/laya` | `english` |
| `convaiinnovations/laya-multilingual` | `multilingual` |
| `convaiinnovations/laya-typed-decisions` | `typed-decisions` |

All three registered with one tokenized root. Twelve shared choice tasks
from the graft suite were sent through the real HTTP quorum.

## Result

The root observed all three checkpoint names, confirming that the identity
fix works.

Cross-lineage divergence was high:

```text
split cases: 11
total tasks: 12
split rate:  91.7%
```

Examples:

| task | english | multilingual | typed-decisions |
|---|---|---|---|
| en01 intent | refund | greeting | refund |
| en05 moderation | spam | ok | spam |
| ml06 intent | invoice | refund | greeting |
| td02 risk | critical | negligible | critical |

This is a harsher comparison than the earlier lineage-specific graft
metrics: every model here answers the same English-biased choice schema.
It should therefore be read as evidence of strong model-specific behavior,
not as a direct replacement for the earlier 32.5% divergence number.

It also reinforces the need for verify/escalate routing: a 2-of-3 majority
can reach `auto` even when the third lineage answers a plausible but
different class.

## Significance

Before this round, the real ONNX HTTP path could not faithfully represent
the claim that the swarm had three distinct Laya lineages. After the fix,
the claim is observable in `/nodes`, vote matrices, rollout attribution,
and quorum selection.
