# Research Round 104 — The declaration chain becomes attributable

Date: 2026-10-14

## The gap

Rounds 102 and 103 made identity declared and the artifact checkable, and
then left the weakest link named explicitly: `rootd --playbook` reads a local
file and trusts it. Whoever can write that file chooses which lineages the
swarm admits and which artifact digests it demands. All the signing
machinery from rounds 82-91 existed and was not connected to it.

## What was built

A detached Ed25519 signature over the playbook's **canonical JSON**, which
already includes `lineages` - so the admitted set and the pinned artifact
digests are inside the signature, not beside it.

```text
tools/sign_playbook.py --playbook p.toml --generate-key
  -> p.toml.sig  {algorithm, pubkey, playbook_hash, signature}

pandosi.rootd --playbook p.toml --playbook-key <pubkey hex>
```

`playbook.load_verified_playbook()` makes three states explicit rather than
conflating them:

| state | meaning |
|---|---|
| unsigned, no key pinned | loads, and the root logs that anyone who can write the file chooses what the swarm admits |
| signed, no key pinned | "self-consistent only" - the signer is whoever wrote the file; logged, not trusted |
| signed + key pinned | checked against an authority; a missing or invalid signature is fatal |

The pinned case is fail-closed at startup: rootd exits rather than serving
under a playbook it could not verify.

## Verification

Signing and verification, on a copy of the example playbook:

```text
signed pb.toml -> pb.toml.sig
pubkey to pin : 39bbe846584352a0fe21831aad1538712b650fe53fc7b30ba05457723389656c

--verify --pinned-key <correct>  -> valid: signature verified against 39bbe846584352a0...
--verify --pinned-key <wrong>    -> INVALID: playbook signed by 39bbe846584352a0...
                                    but 0000000000000000... is pinned
```

Tampering with the *declaration* - adding a `rogue` lineage to `admit`:

```text
--verify --pinned-key <correct>  -> INVALID: Signature was forged or corrupt
rootd --playbook <tampered> --playbook-key <correct>
  -> [playbook] playbook signature rejected: Signature was forged or corrupt
  -> exit 1
```

Positive main path with the untampered playbook:

```text
[playbook] signature verified against 39bbe846584352a0...
[lineages] admitting ['english', 'multilingual', 'typed-decisions']
rootd listening on http://127.0.0.1:8099
```

Smoke coverage (`test_playbook_signature_covers_declarations`): a signed
playbook verifies under its own key; widening `admit` invalidates it; a
pinned key with a tampered playbook raises; a pinned key with no signature at
all raises; and with no pin the loader reports self-consistency rather than
silence. 13 smoke tests pass.

## What this closes

The declaration chain is now attributable end to end: to make a pinned swarm
admit a new lineage, or to make it require a different artifact, an attacker
must produce a signature from the pinned key. Writing the file is no longer
sufficient.

## What it does not close

- **one key signs everything.** The same class of key signs Spore manifests
  and playbooks (round 91). Roles should have separate keys: an artifact
  author, a lineage owner, an operator publishing a strategy. Right now a
  compromise in any one role is a compromise in all of them.
- **the pin is a local value with no lifecycle.** Rotation, revocation and
  expiry are undefined; a pinned key that must be replaced has no procedure.
- **attestation is still a one-time self-report** (round 103): a device can
  register honestly and swap weights afterwards. Periodic re-attestation, or
  a per-decision proof, would be needed.
- **the playbook's authority is not scoped.** A signed playbook can declare
  any lineage and any digest; there is no notion of "this key may admit only
  these artifacts".

The common thread, again: each remaining item is a value carrying an
authority it has not been given a boundary for.
