# Research Round 105 — Self-replication, and the four bugs that were hiding in it

Date: 2026-10-14

## The capability

Every piece of self-replication already existed separately: Spore transfers
a signed payload, a joiner verifies it and becomes a worker, the root admits
declared lineages and requires artifact attestation, and the grant ledger
records that a human approved something sensitive. What was missing was the
loop that puts them in order. `pandosi/reproduce.py` is that loop, and it
decides *before* it moves anything:

```text
plan_reproduction(payload, lineage, target, ...) -> approved | refusals
  - a live `reproduce` grant (operator-approved, expiring)
  - the receiving device confirmed a sandbox
  - the lineage is declared by the playbook
  - the artifact digest matches the digest declared for that lineage
```

Only when every check passes does it start the child, wait for it to
register, and append a **signed** lineage record for the artifact that was
replicated - so a reproduction chains into the same lineage the rest of the
system verifies (rounds 82-91).

## Result

`tools/reproduce_check.py` runs the whole thing with a real `rootd`, a real
parent voter, and a real child launched as `python -m pandosi.join --spore`:

```text
payload laya-en.onnx digest df95fcfba58dc5f1...4aa483
1. no grant        -> approved=False refusals=1
2. wrong digest    -> approved=False (refused before any transfer)
3. granted         -> started=True registered=True voters 1 -> 2
                      lineage generation 0, signed manifest a472baf3a4992...
REPRODUCTION CHECK OK
```

The child pulled a 1.68 GB payload over the Spore endpoints, attested it,
passed admission, and joined the quorum. The run takes about four minutes,
almost all of it the per-chunk transfer.

## The four bugs it found

None of these were visible by reading code, and none was covered by any
existing check. Running the loop end to end is what surfaced them.

**1. `pandosi.join` did not start at all.** A local `import os` inside
`main()` shadowed the module-level import, so the `--pairing-token` default
`os.getenv(...)` raised `UnboundLocalError` during argument parsing. Every
invocation of the replication path died immediately. Fifteen rounds of
checks had never run `join`.

**2. `--serve-spore` did not send the weights.** It served the graph file
under a fixed name `payload.onnx`. For an exported Laya graph that file is a
3 MB protobuf whose weights live in a 1.68 GB `.onnx.data` sibling that the
protobuf references **by name**. Self-replication of a real model was
therefore impossible: the replica received a graph with no weights, and the
attested digest could not match either. Now every file in the artifact set
is served under its original name.

**3. `join` picked an arbitrary file as the model.** `next(iter(manifest["files"]))`
was fine while a payload was one file; with a weight blob present it could
select the `.data` file. It now selects the `.onnx` graph.

**4. `join` never attested.** It did not report `artifact_sha256`, so a root
that declares artifact digests - the round-103 feature - would have refused
every joined node. The attestation work and the join path had never met.

Two smaller ones in the controller itself: the child's stdout was an unread
pipe, which would deadlock a multi-gigabyte transfer once the 64 KiB buffer
filled, and the registration wait would sit out its full timeout even after
the child had already died (nine minutes of waiting for a process that
exited in one second).

## What this changes for the goal

"无限繁殖" now has an executable form on one host: a granted, sandboxed,
declared, attested reproduction that grows the quorum and records itself in
the lineage. The boundary exercised is a process, which is the same shape as
a device - the `Target` carries an argv, so a real second machine is an ssh
invocation away, not a rewrite.

It also produced a useful negative result about the project's own testing:
the replication path was the least-exercised code in the repository and
contained the most severe defect (a total startup failure). Integration
paths that no check runs are where the bugs are, and the two guards added
here are cheap: `join --help` must parse, and the reproduction policy must
refuse for each of its four reasons.

## Open

- the transfer is slow: 26,000 chunk requests for 1.7 GB. A batched or
  ranged transfer, or content-defined chunking with deltas (blueprint
  Phase 5), is needed before replicating across a real network.
- the `Target` abstraction has only been exercised locally; the remote
  command path (ssh, privilege escalation, per-OS adaptation) is designed
  but unbuilt - which is also where the operator-authorisation question
  from the grant ledger becomes practical rather than theoretical.
- a reproduction currently replicates one artifact to one target; there is
  no policy for *how many* replicas a swarm should hold, which is the
  elasticity question rather than the permission question.
