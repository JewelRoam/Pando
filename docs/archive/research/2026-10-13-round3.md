# Research Round 3 — device paths & discovery (2026-10-13 late)

## 1. Android TV boxes can run the harness unmodified (major unlock)

- Termux packages python + python-onnxruntime; the package works on Android,
  importing prints only an "Unsupported platform (android)" warning
  (termux-packages issue #31634, 2026-09). No app packaging required for Phase 1:
  Termux + `pip install onnxruntime zeroconf` + pandosi/ = a working stem on a
  TV box. Blueprint Graft section should name this the **Termux route** and make
  it the default Android onboarding path; an onnxruntime-android AAR app is the
  later Phase-2+ packaging upgrade (official ORT mobile tutorial uses the AAR).

## 2. RK3588 NPU route documented (optimization path)

- rknn-toolkit2 converts ONNX->RKNN: `config(target_platform='rk3588')`,
  `load_onnx(...)`, `build(do_quantization=True, dataset=...)`,
  `export_rknn(...)`; on-board runtime via RKNN-Lite2 (Python) or C API.
- Encoder-family models (MarianMT encoder) already converted successfully by
  community projects; Laya (ModernBERT/mmBERT encoder) conversion is plausible
  but must be validated: known failure classes are unsupported ops
  (e.g. NonMaxSuppression), opset-version sensitivity (>=19 recommended for
  torch exports), and int8 quantization needing a calibration dataset.
- laya-on-rk3588-jetson already ships RKNN recipes + 509 ms measured latency
  (round 2). Amlogic S905-class boxes have no usable NPU for ONNX; they take
  the Termux/CPU route. Keep RKNN as an opt-in accelerator for RK3588 devices.

## 3. LAN discovery: python-zeroconf chosen

- python-zeroconf is pure-python mDNS/DNS-SD (register/browse), works with a
  stdlib HTTP server; canonical usage is ~10 lines (examples/registration.py).
  Decision: service type `_pandosi._tcp.local.`, TXT records carry
  {node_id, checkpoint, role, version}. SCAN phase of Spore uses browsing of
  this service type; wide-area/WAN joining stays heartbeat/URL-based.

## 4. Amlogic S905 status unchanged

- No NPU ONNX path; Termux/CPU route applies. The 4-8 tok/s LLM estimate from
  round 1 remains inference-only; Laya-class single-forward decision latency on
  S905 is still unmeasured and remains the Phase-1 benchmark target.
