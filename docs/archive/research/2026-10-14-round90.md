# Research Round 90 — Cached parent lineage verification

Date: 2026-10-14

## Problem

Generation and parent hashes were verified in memory while constructing a
multi-hop chain, but a receiving node did not persist manifests by hash.
After transfer, it could record provenance but not independently re-check a
cached parent later.

## Change

Added a manifest cache:

```text
spore-cache/<node>/manifests/<manifest_hash>.json
```

`validate_cached_lineage()` returns one of:

```text
valid           parent present and generation/hash match
parent-missing  child recorded but parent not available locally
invalid         parent present but signature or generation linkage fails
```

`join --spore` now stores the received manifest and validates against a
cached parent when one is available.

## Verification

The three-hop chain now verifies cached lineage at B and C:

```text
cached parent lineage verified
```

The DAG check also verifies:

```text
uncached parent reported as parent-missing
cached generation mismatch rejected
```

This preserves the important distinction between “not enough history to
verify” and “history present and contradictory”.

## Remaining limitations

- a parent can still be missing on a node that only receives a descendant;
- all manifests currently use one signing key;
- there is no peer query for fetching a missing parent manifest;
- merge semantics for multi-parent nodes are undefined.
