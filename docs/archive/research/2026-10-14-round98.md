# Research Round 98 — Can it find its own decisions and act? No, and here is what it can do

Date: 2026-10-14

## The question

Asked directly of this project: does a small decision model like Laya need a
larger model to hand it a frame ("here are four options"), or can it find
things to decide and act on them by itself?

Laya ships an **act head** — an extra output, `act_logits`, separate from the
choice head — which looks exactly like the mechanism that would answer this.
So this round tested it first.

## Finding 1: the act head is saturated (measured, both ecosystems)

Eight states, chosen to span acting and not-acting: a build failure, a
credential-phishing email, a greeting, a name question, a refund demand,
small talk, a heartbeat log line, and a telemetry sample. Each was answered
through ONNX Runtime (CPU) and native PyTorch (CUDA):

```text
state      onnx_act   torch_act   onnx choice   torch choice
error        1.0        1.0        ignore        ignore
threat       1.0        1.0        ignore        ignore
greeting     1.0        1.0        act           act
info         1.0        1.0        act           act
refund       1.0        1.0        act           act
chat         1.0        1.0        act           act
silence      1.0        1.0        ignore        ignore
noise        1.0        1.0        ignore        ignore
```

`act_probability` is 1.0 for every state in both ecosystems, including the
two that warrant no action at all. Running both runtimes rules out an ONNX
export artifact: the saturation is in the checkpoint, not in our graph.

**So the answer is no.** The model cannot decide *whether* to engage; it can
only answer a question it is handed. Something outside it must produce the
observation and the question. Laya supplies a calibrated confidence
(`answer_confidence`) and the package offers abstention-threshold fitting
(`laya.calibrate`), which is a "how sure am I" signal — not a "should I
speak up" trigger.

## Finding 2: the swarm already has the gate, but the gate has a hole

The coordinator computes `tier` (`auto` / `verify` / `escalate`) from
agreement and confidence. That is the closest thing in the system to "I am
competent here", so this round used it as the autonomy gate — and while
testing it, found a real problem.

`Coordinator.decide()` aggregates with `min_quorum=min(3, len(selected))`.
When the swarm shrinks, the threshold shrinks with it, so **a single
surviving voter returns `tier=auto` with agreement 1.0**:

```text
degraded quorum: held (tier=auto, responded=1/1,
                      reason='only 1 responders; policy requires 3')
```

An autonomous loop gated on the tier alone would have acted on one machine.
The gate has to be two-part: the swarm's verdict *and* a minimum number of
responders.

## What was built

`pandosi/autonomy.py` — the observe -> decide -> act half of the loop:

- `Observation` (a thing noticed), `RootDecider` (the ordinary `/decide`
  call), `Journal` (append-only record of every outcome, acted or held);
- `AutonomyLoop(allowed_tiers=("auto",), min_responders=3)`: it acts only
  when the swarm's tier is allowed **and** enough voters answered, and it
  records everything else as held, with the reason. Acting is a pluggable
  callback; the loop owns only the safety property.

`tools/autonomy_check.py` runs it end to end against a real `rootd` and real
`stemd` workers:

```text
full quorum: acted 2/2 (tiers ['auto', 'auto'])
degraded quorum: held (tier=auto, responded=1/1, reason='only 1 responders;
                      policy requires 3')
journal: 2 recorded outcomes
actions: ['obs-1->retry', 'obs-2->allow']
AUTONOMY LOOP OK
```

## The honest answer to the question

| capability | evidence |
|---|---|
| find its own decisions | **no** — the act head saturates at 1.0 in both ecosystems; an external source must produce the observation and the question |
| choose among options well | yes, ~56% on the English suite, identical across ecosystems (round 95) |
| know when it is guessing | partly — calibrated confidence exists, thresholds are not fitted by default |
| know when it is alone | no, not from the tier; requires an explicit responder policy (this round) |
| act, and refuse to act | yes, with both gates in place (this round) |

That is a coherent division of labour for the goal: the swarm provides
**competence and refusal**, and it needs an **outside agenda** — an
observation source and a task selector — which is exactly the part a
larger model would supply, and the part that would have to be built next if
"self-directed" is wanted.

## Next step

Fit the abstention thresholds on the labeled suite and measure the
risk-coverage curve of the two-part gate: at what coverage does the
acted-only set beat 55.6% accuracy, and how much work is held. That turns
"know when it is guessing" from "partly" into a number, and it needs no new
hardware.
