# Research Round 2 — 2026-10-13 (evening)

Sources: web search snapshots; indexes unless marked live.

## 1. Laya toolchain specifics (live reads)

- pip package `laya`: `laya.load("convaiinnovations/laya")`, `.decide(state, question, ...)`;
  decide also works on Router; `predict_batch` shares forward passes; pydantic structured
  mode via `laya[structured]`; FastAPI server via `laya[serve]` (/predict, /predict/batch).
  Payload wire-compatible with Jev clients (choice/score/noul + usage block).
- ONNX path is first-class: `scripts/export_onnx.py --model ... --output laya.onnx --quantize`
  (dynamic int8); ONNXAgent loads by onnx_path. eval harness `laya-evals --max-ece 0.05`.
- **INT8 caveat (official docs)**: dynamic int8 "trades real accuracy... do not use it
  where the calibrated probability or confidence matters". Root consensus depends on
  calibrated probabilities -> quantized workers must pass an ECE gate before admission.
- **laya-on-rk3588-jetson (live repo)**: laya-multilingual on RK3588 (RKNN) = **509 ms**,
  Jetson Orin NX (TensorRT) = **18.9 ms**, 16/16 acceptance protocol. First real ARM
  SoC numbers for Laya. RK3588 is TV-box-class silicon; Amlogic S905 still untested.
- laya-rs2 0.3.1 (Rust/candle): full inference + RLCD Trainer, no Python at runtime.
  Future single-binary harness candidate for locked-down devices.
- **laya-evals + preregistered reproduction (arXiv:2609.33843)**: the shipped
  typed-decisions checkpoint is **uniformly under-confident** (independent study).
  Implication: tier gating thresholds must sit behind a per-checkpoint recalibration
  layer (temperature/Platt), validated by ECE, not raw model probabilities.

## 2. Consensus diversity — the literature is unambiguous

- arXiv:2605.29800 "Nine Judges, Two Effective Votes": 9 frontier LLM judges from 7
  families carry only ~2 independent votes of information on NLI tasks. Correlated
  errors are the norm, not the exception.
- HF/arXiv:2602.03794 (agent scaling via diversity): homogeneous scaling has strong
  diminishing returns; **2 diverse agents match or exceed 16 homogeneous** at equal
  compute; heterogeneity (models/prompts/tools) is the axis that pays.
- MDPI Appl.Sci. 2026 "When Agents Disagree": diverse team + judge selection = 0.810
  win rate vs 0.512 homogeneous; BUT homogeneous Self-MoA wins under synthesis-style
  aggregation. For typed decisions (selection not synthesis), diversity + voting wins.
- arXiv:2502.19130: voting beats consensus protocols on reasoning tasks (+13.2%);
  consensus beats voting on knowledge tasks (+2.8%). Protocol should be task-aware.
- Nature MI 2026: capable centralized heterogeneous configs underperform homogeneous
  strong baseline; decentralized mixed teams ~match it. Supports thin-root design:
  the coordinator must not be the smartest node, just the busiest.

**PandoSI implications**:
1. Quorum diversity is now quantitatively mandatory, not a nicety. 3 Laya checkpoints
   + temperature + schema variants give ~3-5 effective diversity axes; beyond that,
   gains require per-device fine-tuned lineages -> directly links Phase 5 (RLCD) to
   consensus quality, not just capability.
2. Aggregation should be selection/voting for reasoning-type questions; keep
   probability-mean only as tiebreak for knowledge-type questions.
3. Root stays thin (routing/aggregation only). No LLM in the hot path.

## 3. Safety gate prior art (directly reusable)

- Laya Guard: 184M DeBERTa-v3 guard scoring agent tool calls pre-execution,
  AUROC 0.855 on R-Judge held-out (304 trajectories). pypi `laya-guard`:
  deterministic pattern rules first, decision model only for the gray zone,
  fail-closed posture documented. This is exactly the two-tier gate Spore needs:
  deterministic rules -> gray zone -> decision model quorum -> (still gray) escalate.

## 4. Transport

- LAN decision latency budget (300-500 ms model) dwarfs transport overhead:
  gRPC UDS ~116-167 us RTT; Zenoh ~10-21 us; plain HTTP/TCP ~0.5-2 ms on LAN.
  Stdlib HTTP/JSON is adequate for Phase 1; upgrade path nng/Zenoh only if
  profiling shows serialization is a top-3 cost. Benchmark source: Hitachi
  messaging-libraries-benchmark + areg-sdk wiki.
