# Research Round 76 — Canonical RLCD question schemas

Date: 2026-10-14

## Problem

Round 75 exposed a silent data bug:

```text
Conflicting schema detected for question 'intent' across rows;
keeping first seen definition.
```

The same prompt name (`intent`) appeared with different candidate sets, so
the trainer merged incompatible label spaces by keeping whichever schema it
saw first.

## Fix

`common.canonical_question(question, candidates)` now produces:

- a stable question id from the prompt name and option-set digest;
- a sorted, de-duplicated option order.

Both the live ONNX backend and `rollout.export_training_rows()` use this
function. Example:

```text
intent + [refund, complaint, greeting] -> intent.3c49d9ff
moderation + [spam, ok]                -> moderation.a844be57
```

Different option sets now become different question heads instead of being
silently collapsed.

## Validation

The unit suite verifies:

- reordered options map to the same canonical id;
- a different option set maps to a different id.

`tools/export_rlcd.py` re-exported 10 contrast rows with canonical ids.
Retraining on `artifacts/rlcd-cuda-v3` produced no schema-conflict warning.

## CUDA v3 run

```text
train items:       9
optimizer updates: 9
mean loss:         0.4342
wall time:         9.329 s
peak CUDA memory:  2024.1 MB
```

The loss is not directly comparable to v2 (`0.2107`): v3 separates question
schemas that v2 had merged, so the label spaces and heads changed.

Decision stability remained:

| metric | value |
|---|---:|
| English accuracy before | 0.7857 |
| English accuracy after | 0.7857 |
| labels preserved | 14/14 |
| max confidence delta | 0.1720 |

## Remaining data gaps

- only one calibration item, below the trainer's minimum of ten;
- no independent held-out evaluation file;
- ten contrast pairs are still too few to claim generalization.

The next milestone is more schema-normalized, independently evaluated
contrast data, not more epochs on the current ten rows.
