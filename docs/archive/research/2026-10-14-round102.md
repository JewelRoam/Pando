# Research Round 102 — Declared lineage identity

Date: 2026-10-14

## What round 100 and 101 left open

Calibration is selected by the checkpoint string a stem reports, so a
misnamed device silently ran a different gate. Round 101 put the enforcement
where the risk is (the acting loop), but a *name* was still the only
identity the swarm had.

## What was built

Identity is now declared, and a declaration has to be honour-able.

```toml
[lineages]
admit = ["english", "multilingual", "typed-decisions"]
```

- `playbook.load_playbook()` parses and validates the block: a non-empty
  list of non-empty, duplicate-free ids, or a startup error.
- `playbook.resolve_admitted_lineages()` admits an id only if it is declared
  **and** `assets/calibration/<id>.json` exists. A declared id with no
  temperature table is reported as unusable and is not admitted.
- `rootd` refuses at admission: `POST /register` with an undeclared
  checkpoint returns `403` plus the admitted set, and prints the admitted
  lineages at startup. A playbook whose declarations are *all* unusable is a
  fatal configuration error rather than a silently open swarm.
- A root with no declared lineages stays permissive. That is deliberate: it
  keeps every synthetic harness and the round-100 gate check working, which
  is exactly what the first attempt at round 101 got wrong.

## Verification

Main path, real `rootd` started with `assets/playbook.example.toml`:

```text
[lineages] admitting ['english', 'multilingual', 'typed-decisions']
declared english    -> (200, {'ok': True})
undeclared english2 -> (403, {'error': "lineage 'english-v2' is not declared
                                by this playbook",
                              'admitted': ['english', 'multilingual',
                                           'typed-decisions']})
```

New smoke test (`test_declared_lineages_gate_registration`):

```text
admit = ["english", "not-a-real-lineage"]
  -> admitted {'english'}, unusable ['not-a-real-lineage']
  -> declared stem registers 200; undeclared stem 403 and absent from /nodes
```

Regression: 12 smoke tests OK, and `tools/gate_e2e_check.py` still reports
coverage and accuracy deltas of 0.0000 against its offline prediction.

## What this closes, and what it does not

**Closed:** a device that reports an unexpected lineage cannot join a swarm
that declares its lineages, and an operator cannot admit a lineage whose
confidence scale is unknown. Identity, admission and calibration now all
derive from one declaration instead of three implicit conventions.

**Not closed: a declaration is a claim, not proof.** A stem can still
register as `english` while executing something else entirely; it will be
admitted, and its votes will be calibrated as English. Admission control
stops *misnaming*, not *impersonation*.

Closing that needs **attestation**: the stem should report the artifact it
actually loaded (the Spore manifest hash of the graph, from rounds 82-91)
and the root should require it to match the manifest the declared lineage
was admitted under. The pieces already exist - signed manifests, content
hashes, a pinning rule for the seed key - they are simply not connected to
registration. That connection is the next step, and it is also what would
let the single signing key from round 91 become a per-lineage key.

## Note on the shape of these three rounds

Rounds 100-102 are all the same species of defect: a value used as though it
carried a guarantee it did not (a name implying a calibrated model;
three-way ties implying coverage; a declaration implying identity). None was
found by reading the code; each surfaced from computing a metric and asking
what it was actually measuring.
