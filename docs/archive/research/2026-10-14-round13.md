# Research Round 13 — iGPU revived by graph surgery (2026-10-14)

## Breakthrough: GPU EU now compiles and runs 4x faster than CPU

`tools/fix_gathernd.py` rewrites GatherND (data rank-2, index_depth 2) into a
supported chain: Reshape/Slice/Squeeze (split outer/inner index) -> Gather
(rows by outer idx) -> Unsqueeze/GatherElements (pick inner idx per row) ->
Reshape (restore indices shape minus depth).

- Numerical equivalence vs the original graph verified on CPU (allclose, max
  diff 0) with the real captured input batch.
- GPU (Arc 140T iGPU): compile 8.0 s, **p50 25.6 ms / p95 27.6 ms** - 4x
  faster than the CPU EU (106 ms). Stable across 20 runs.
- NPU: still rejected (more unsupported ops than GatherND in the graph) -
  remaining NPU work: NNCF PTQ U8 export path or deeper op substitution.

## Consequences

- Single-device Shape B becomes truly heterogeneous: iGPU replica (25.6 ms)
  + CPU replicas - and GPU-vs-CPU floating-point paths even add a small
  natural numerical diversity on top of checkpoint diversity.
- HETERO/MULTI remain unnecessary for now: a dedicated iGPU worker beats the
  mixed-device schedule.
- The surgery is generic for GatherND(data rank-2, depth 2) graphs and is
  now part of tools/ for future checkpoint exports.
