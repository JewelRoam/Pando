# Research Round 61 — adversarial robustness matrix (2026-10-14)

## Adversarial robustness: exact safety boundaries quantified

| honest | adversarial | tier | correct | status |
|---|---|---|---|---|
| 5 | 0-3 | auto | yes | ✅ safe to 37.5% adversarial |
| 4 | 0-2 | auto | yes | ✅ safe to 33% adversarial |
| 4 | 3 | verify | yes | ✅ correctly demoted |
| 3 | 0-2 | auto | yes | ✅ safe to 40% adversarial |
| 3 | 3 | verify | None | ✅ correctly refused |
| 2 | 2 | verify | None | ✅ correctly refused |
| 2 | 3 | **auto** | **no** | ⚠️ DANGEROUS |
| 1 | 2+ | **auto** | **no** | ⚠️ DANGEROUS |

## Key findings

1. **SAFE when honest ≥ adversarial**: the 0.6 auto_min_agreement threshold
   prevents adversarial takeover when honest voices are equal or majority.
2. **CORRECTLY DEMOTED at parity**: 4:3 and 3:3 correctly drop to verify
   (not auto) - the system knows when it is uncertain.
3. **DANGEROUS when honest < adversarial**: this is the Byzantine Generals
   problem - no voting system can solve it without a trusted source.

## Mitigations (already in the architecture)

1. **Checkpoint diversity**: an adversary must compromise multiple lineages,
   not just inject more stems (checkpoint diversity is enforced).
2. **EU diversity**: an adversary must compromise multiple backends
   (EU diversity is the design principle).
3. **Sandbox gate**: unauthorized stem creation is blocked (lab.py).
4. **Spore signature**: unauthorized playbooks are rejected (Ed25519).
5. **Informational isolation**: score heads cannot gate actions.

## Conclusion

The governance pipeline is robust to adversarial takeover when checkpoint
diversity and EU diversity are maintained. The vulnerability is only when
an adversary controls MORE stems than honest ones, which requires
compromising multiple independent lineages AND multiple execution units.
