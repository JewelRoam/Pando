# Research Round 32 — per-dim buckets fail at graph level; static export is the path (2026-10-14)

- Implemented per-dim-position buckets (batch exact, seq 128, markers 8).
- Result: MatMul shape-inference failure inside the graph - internal Reshape
  ops fold batch/markers/seq non-trivially ([8,128,16384] activations), so
  inference-time padding with naive per-dim rules cannot work. The graph's
  shape graph is only consistent for shapes seen at export time.
- Correct path (designed, next session): STATIC-SHAPE exports. Export one
  ONNX per bucket with fixed shapes (batch=1, seq in {64,128,256,512}) from
  torch.onnx.export without dynamic_axes; the OV shim then picks the
  smallest bucket >= input and pads. Numerical equivalence verified per
  bucket against natural-length ORT outputs.
- pad_to mode in _OVLazySession remains correct for SINGLE-SHAPE serving
  (one compiled bucket); the multi-bucket generalization needs the static
  exports above.
- Honest status: iGPU variable-length serving remains open engineering
  (est. half-day: export wrapper + per-bucket verification).
