# Research Round 5 — single-device heterogeneous assembly (2026-10-13)

Question: can one AI PC (CPU + iGPU + NPU + external GPU, shared memory) host
a fully elastic assembly, or is one compute unit per device the limit?

## Answer: supported natively today

- OpenVINO HETERO mode: splits the model by layers into subgraphs assigned to
  devices by priority (HETERO:GPU,CPU; NPU and multiple GPUs supported; greedy
  auto-assignment via ov::device::priorities). Official caveat: if inter-subgraph
  transfer cost exceeds the benefit, hetero "may be unsubstantiated" — split
  point must be measured, not assumed.
- OpenVINO MULTI mode: one model, many devices, request-level parallelism
  (MULTI:GPU.1,GPU.0). iGPU enumerates as GPU.0, dGPU as GPU.1. Needs enough
  in-flight requests to pay off — PandoSI fan-out voting has natural concurrency.
- The two modes compose (MULTI_DEVICE_PRIORITIES on HETERO).
- ipex-llm: Intel XPU stack (CPU/iGPU/NPU/dGPU) for LLMs; pipeline-parallel
  inference across 2+ Intel GPUs (2024-06+); tensor-parallel on multi-Arc;
  self-speculative decoding ~30% speedup.
- ONNX Runtime: one session = EP fallback chain (node runs on first capable EP);
  hard limit: one EP instance per session, so iGPU + dGPU in ONE ORT session is
  impossible -> use two sessions or OpenVINO for multi-GPU.

## Hardware topology truth

- iGPU + NPU share system RAM (near-zero-copy transfers) BUT share the same
  memory bandwidth controller -> concurrent saturation causes contention.
- dGPU / external GPU: private VRAM + PCIe transfers with real cost.
- So per-unit affinity matters; blanket "use everything" is not optimal.

## NPU constraints (confirmed by docs + open issues)

- Static shapes only (dynamic shapes = limited preview; Qwen3-0.6B INT4 compile
  bug open on Lunar Lake). Quantized data types U8 / INT8 / mixed FP16-INT8.
- Laya is a fixed-length encoder (512/1024 ctx) -> NPU-friendly, but batch must
  be padded to a static size.

## PandoSI architecture consequence (blueprint v0.6)

Atomic resource unit changes from Device to ExecutionUnit (EU):
- one AI PC = up to 4 EUs (CPU / iGPU / NPU / dGPU)
- assembly shapes: (A) single worker + HETERO backend; (B) multiple virtual
  stems, one per EU, each holding a Laya replica in the quorum (feeds the
  diversity requirement directly); (C) mixed: NPU for hot low-latency calls,
  CPU for calibration/management, GPU for drafts.
- elasticity: plugging an external GPU = a new EU online = a Graft event.
  Same Stem/Root/Graft protocol spans EU -> device -> cluster levels.
- Graft capability probe must enumerate EUs (OpenVINO core.available_devices,
  or DXVA/LevelZero enumeration) instead of assuming one accelerator.
