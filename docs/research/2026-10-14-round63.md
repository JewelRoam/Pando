# Research Round 63 — security gating: per-category thresholds (2026-10-14)

## The security blind spot (round 62b) is now FIXED

The stability map found that all 3 lineages judge "login from new device"
as "normal" when it should be "suspicious". The fix: security questions
get LOWER thresholds (0.5/0.4 vs global 0.6/0.6) because the cost of a
false negative (missing a threat) is higher than a false positive.

## Implementation

- playbook.example.toml [gating.security] section: auto_min=0.5/0.4
- rootd decide(): detects security questions by keyword and applies
  the stricter gating from the playbook [gating.security] section
- Live smoke: security_check question -> suspicious -> tier=auto
  (3/3 responded, lower threshold correctly applied)

## Design principle

Per-category thresholds are a playbook feature, not a code change:
the playbook author decides which categories need stricter gating.
The rootd just applies whatever the playbook says.
