# Research Round 85 — Installable package and runtime extras

Date: 2026-10-14

## Packaging change

Added explicit optional extras:

```toml
[project.optional-dependencies]
lan = ["zeroconf>=0.131"]
onnx = ["onnxruntime>=1.18", "numpy>=1.26"]
cuda = ["onnxruntime-gpu>=1.31"]
runtime = ["zeroconf", "onnxruntime", "numpy"]
```

The base wheel still needs only PyNaCl. The runtime extras cover local and
LAN serving without pulling in PyTorch or model tooling.

## Isolated install verification

`tools/package_check.py` creates a temporary venv, builds/installs the
repository, and runs the installed `pandosi` console script outside the
source tree.

Base install:

```text
pandosi --version       -> pandosi 0.0.1
pandosi doctor --json   -> ok
zeroconf                 -> miss
onnxruntime              -> miss
```

`--extras lan,onnx`:

```text
pandosi --version       -> pandosi 0.0.1
pandosi doctor --json   -> ok
zeroconf                 -> ok
onnxruntime              -> ok
```

The wheel built in both cases. The console script worked from a directory
outside the repository.

## Why this matters

The project previously worked only as a source checkout with undeclared
runtime packages. The install path is now:

```bash
pip install pandosi[runtime]
```

Optional CUDA remains isolated because `onnxruntime-gpu` may conflict with
the CPU runtime used by Intel stems.

## Remaining packaging gaps

- no PyPI publication yet;
- model weights and graft assets are not bundled in the wheel;
- CUDA still requires the separate `.venv-cuda` workflow;
- service installation is intentionally not part of package installation.
