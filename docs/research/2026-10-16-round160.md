# Research Round 160 — Live, the three-tier fleet beats its core (0.9833, replicated)

Date: 2026-10-16

Round 159's offline matrix predicted it and named the rule; this round ran
it on real hardware and the prediction held to the digit.

## The fleet

Three tiers, two machines, Windows -> Mac direction only:

| tier | hardware | member |
|---|---|---|
| Laya floor | Intel iGPU (OpenVINO static graph) | `english` |
| the project's fine-tune | RTX 3070 (torch/CUDA) | `ft-v3` |
| real LLM | Mac Qwen3-4B-Instruct-2507 (llama.cpp/Metal), B-prompt, over the LAN API | `mac-llm` |

Root: quorum 3/3, shipped combiner, **`--assent-checkpoint ft-v3`** (auto
only when ft-v3's vote matches the aggregate choice; otherwise the row goes
to the advisor like any other declined row). Split D, 240 rows, evaluator
only.

## The result

| run | auto | auto acc | suggestions | decided | p50 |
|---|---:|---:|---:|---:|---:|
| live run 1 | 195 | **1.0000** | 45 @ 0.9111 | **0.9833** | 182 ms |
| live run 2 (replication) | 195 | **1.0000** | 45 @ 0.9111 | **0.9833** | 181 ms |

Against the record: the two-member core (`english + ft-v3`) decided 0.9750
with 159 auto rows; the naive seating of the same LLM tier decided 0.9167
(round 158); the offline prediction was 0.9833 with ~199 auto rows.

## What it establishes

**A third, weaker tier now improves the system live.** +0.83 points of
decided accuracy over the core, with 36 more rows auto-executed and every
one of them correct. Weak-tier coverage and strong-tier precision stopped
being a trade the moment the gate started requiring the trusted member's
assent.

**The design rule survived contact with real hardware.** Nothing about the
offline model changed when the third vote arrived over a LAN at ~139 ms per
row from a different OS and architecture: same members, same rule, same
number. "Tiered composition lifts a system when the gate lets the
highest-accuracy member hold the veto" is now a live finding, not a
spreadsheet one.

**Replication discipline:** two full runs, identical to the digit on every
quality metric (throughput 5.60 rows/s, p50 181-182 ms). The four-row gap in
auto count versus the offline matrix (195 vs 199) is exercised-scope: the
backend serves the B prompt with `max_tokens=16`, the Mac's offline run used
64; a handful of rows parse slightly differently. decided accuracy is
unaffected.

## Honest edges

- The assent member is fixed at ft-v3 for now; the general policy (assent =
  measured-best member present) needs a measured-accuracy registry, not a
  hard-coded name.
- `mac-llm` still carries constant p=0.5 - it is a choice-only tier under
  this prompt; the gate treats its confidence as neutral by construction.
- The live run's per-stem `/health` counts were lost to a name-mapping bug
  in the checker's report (fixed after); the quality numbers themselves are
  unaffected and recorded.
- D has been the evaluator for many configurations; a fresh wording split
  (E) would be the honest next evaluation before any stronger claim.
