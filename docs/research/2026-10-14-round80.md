# Research Round 80 — Live A/B placement of the v7 candidate

Date: 2026-10-14

## Export

The v7 PyTorch checkpoint was exported with the official Laya ONNX exporter:

```text
artifacts/laya-rlcd-v7.onnx       3.44 MB
artifacts/laya-rlcd-v7.onnx.data  1.685 GB
```

The graph exposes the same five inputs and two outputs as the baseline. Both
baseline and candidate were then loaded as real CPU HTTP stems:

| stem | checkpoint | source |
|---|---|---|
| baseline | `english` | `artifacts/laya-en.onnx` |
| candidate | `rlcd-v7` | `artifacts/laya-rlcd-v7.onnx` |

## Live A/B result

Six held-out tasks were sent through the real tokenized root:

```text
decision agreement: 6/6 (100%)
baseline accuracy:  0.5
candidate accuracy: 0.5
```

The candidate did not add a new correct decision. It also did not diverge
from the baseline on this holdout slice.

## Confidence behavior

The candidate moved confidence sharply:

| task | baseline confidence | v7 confidence |
|---|---:|---:|
| en01 refund | 0.8696 | 1.0000 |
| ml04 risk | 0.4329 | 0.3965 |
| td04 action | 0.4976 | 0.5666 |
| ml12b wrong refund | 0.7590 | **0.9996** |
| td06 route | 0.5834 | 0.9247 |
| td08 followup | 0.6912 | 0.9974 |

The wrong `ml12b` answer is again the decisive result: v7 is almost maximally
confident while still wrong.

## Promotion decision

v7 is **not promoted** as a replacement lineage. It is retained as a
candidate artifact and as evidence that the live A/B path works.

The next candidate must demonstrate either:

- a held-out label correction, or
- better calibration at equal accuracy,

before it can replace the baseline.
