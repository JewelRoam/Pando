# Research Round 77 — Held-out evaluation after CUDA RLCD

Date: 2026-10-14

## Purpose

Round 76 removed the schema conflict, but the previous 14-task English
comparison contained training overlap. This round removes every evaluation
task whose state appeared in the training rows and measures what remains.

## Protocol

- training data: `rollouts/train_rlcd_all.jsonl` (9 train items, 1
  calibration item);
- evaluation source: the complete 40-task graft suite;
- candidates: all lineages;
- exclusion: exact duplicate states present in training rows;
- result: **9 overlapping tasks excluded, 31 held-out tasks evaluated**.

Both checkpoints were evaluated by the same code path on the same 31 tasks.

## Result

| metric | original | CUDA v4 |
|---|---:|---:|
| held-out accuracy | 0.6129 | 0.6129 |
| label agreement | - | **31/31** |
| max confidence delta | - | **0.1856** |
| training overlap removed | 9 | 9 |

No held-out labels changed. The fine-tune changed confidence substantially,
but did not improve or damage accuracy on this held-out slice.

## Interpretation

This is a useful negative result:

- the CUDA training pipeline is deterministic enough to preserve every
  held-out label;
- ten contrast pairs and one epoch are not enough to produce observable
  generalization improvement;
- confidence movement without accuracy movement is not evidence of learning
  a new decision boundary;
- reporting only the previous 14-task English slice would have overstated
  the evidence because part of it overlapped training.

## Next data requirement

The next evolution run should not simply increase epochs on the same ten
rows. It needs:

1. more independent state/question schemas;
2. a fixed held-out suite that is never used for export or calibration;
3. enough calibration rows to fit temperature;
4. lineage-stratified results, not just aggregate accuracy.
