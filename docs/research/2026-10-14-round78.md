# Research Round 78 — Train/holdout split and confidence overfitting

Date: 2026-10-14

## Protocol

`tools/build_suite_split.py` deterministically split the 40-task graft suite:

```text
train:   34 tasks
holdout: 6 tasks
holdout ids: en01, ml04, td04, ml12b, td06, td08
```

The real en/ml/td HTTP swarm ran only the training suite. Of 34 decisions,
24 had cross-lineage splits and 20 contrast rows were exported to
`artifacts/graft-train-rlcd.jsonl`.

The six held-out tasks were never used for training, calibration, or export.

## One epoch: v5

```text
train items:       18
calibration items: 2
optimizer updates: 18
mean loss:         0.1179
wall time:         9.927 s
peak CUDA memory:  2024.1 MB
```

Held-out result:

```text
accuracy:        0.6667 -> 0.6667
labels:          6/6 unchanged
max confidence delta: 0.1627
```

## Four epochs: v6

The same data was trained for four epochs:

```text
optimizer updates: 72
epoch mean losses: 0.1137, 0.0466, 0.2319, -0.2153
wall time:         13.757 s
```

Held-out result:

```text
accuracy:        0.6667 -> 0.6667
labels:          6/6 unchanged
max confidence delta: 0.2649
```

Confidence was pushed toward saturation:

```text
en01: 0.9788 -> 1.0000
td04: 0.7195 -> 0.9844
td06: 0.7378 -> 0.9541
td08: 0.8608 -> 0.9978
ml12b incorrect refund: 0.9716 -> 1.0000
```

The last case is the key failure mode: an incorrect held-out decision became
more confidently wrong.

## Interpretation

More optimizer updates on the same small dataset did not create a better
decision boundary. They primarily increased confidence, including on a wrong
answer. The held-out accuracy remained unchanged.

This supports stopping the current training branch. The next training run
needs new independent contrast data and calibration, not more epochs.

## Calibration limitation

Only two calibration items were available:

```text
choice: not fitted: 2 calibration items, fewer than 10
```

The in-sample calibration slice worsened after four epochs:

```text
loss:  1.0768 -> 2.3244
Brier: 0.7806 -> 1.0263
mean confidence: 0.6272 -> 0.8683
```

This is additional evidence that v6 should not become a default lineage.
