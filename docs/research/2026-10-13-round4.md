# Research Round 4 — protocol details (2026-10-13 night)

## 1. Spore signature scheme settled

- Ed25519 via PyNaCl (`nacl.signing.SigningKey` / `VerifyKey.verify(msg, sig)`),
  the de-facto Python standard. Signature covers a small JSON manifest, never
  the ~800MB weights directly.
- Weights verified by chunk hashing + Merkle tree: each chunk (64KiB) hashed,
  leaves form a binary Merkle tree, root hash lives in the signed manifest.
  Benefits: verify-on-arrival per chunk, re-fetch only corrupted chunks, and
  partial-trust check before full transfer completes (Swarm/BitTorrent pattern;
  cf. Bittorrent chunking, EthSwarm binary Merkle with Keccak256, content-defined
  Merkle trees arXiv:2104.02158).
- Content-defined chunking (CDC) is the Phase-5 hook: when lineage v(n+1)
  fine-tunes only part of the model, unchanged chunks are shared with v(n), so
  Spore transfer of an evolved swarm moves only deltas (~1% transfer for a
  single-chunk edit in the reference measurement).

## 2. File formats settled

- playbook: **TOML** (human-authored, explicit types, RFC 3339 dates, no YAML
  coercion ambiguity); wire/API: **JSON**; prompt/eval datasets: **JSONL**
  (matches laya-evals data.jsonl); integrity: manifest.json (signed).

## 3. Graft acceptance set

- Borrow laya-on-rk3588 structure: fixed 16-task decision set with known
  expected answers; acceptance = 16/16 correct + p50/p95 latency + ECE report.
  Tasks span the three question types (choice/score/noul) and the three
  checkpoints. Published per-device; the dataset itself is open contribution.
