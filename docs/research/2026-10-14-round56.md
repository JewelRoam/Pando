# Research Round 56 — 🎉 TRIPLE EU CONSENSUS OK (2026-10-14)

## THE MILESTONE

One command. One AI PC. Three heterogeneous execution units. One consensus.

```
join --multi-eu --backend onnx --onnx-path laya-ml.onnx

  aipc      (CPU · ORT · ml 血统):      greeting @ 0.532
  aipc-gpu  (iGPU · OpenVINO · en 血统): refund  @ 0.9884
  aipc-npu  (NPU · OpenVINO · en 血统):  refund  @ 0.988
  → refund | tier=auto | agreement=0.67 | 3/3 responded
```

## What this proves

1. **Three heterogeneous execution units** (CPU/iGPU/NPU), each with a
   different backend (ORT/OpenVINO-GPU/OpenVINO-NPU), each with a
   different or same checkpoint (ml/en/en), ALL voting in the same quorum.
2. **Persistently registered** (heartbeat working): all 3 stayed in /nodes
   for 80+ seconds.
3. **Genuine lineage dissent**: ml-CPU voted differently from en-iGPU/NPU
   (phrasing sensitivity from round 51d) - and the quorum correctly
   identified the majority and auto-executed.
4. **Cross-EU numerics**: iGPU and NPU produce slightly different results
   (0.9884 vs 0.988) but agree on the choice - independent verification.

## The NPU fix

join --multi-eu NPU stem was missing pad_to=256 - the static graph received
an unpadded [1,15] feed and crashed. One line fix. This is why integration
testing matters: the NPU works in isolation but the integration path had
a missing parameter.

## What this closes

This is the final piece of the original question: "can one device do
heterogeneous elastic assembly?" The answer is definitively YES, verified
on real hardware, with real model weights, real consensus, real governance.
