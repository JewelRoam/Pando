# Research Round 51c — NPU deep-dive: dynamic dims persist inside the graph (2026-10-14)

## Attempted
1. Surgery graph (GatherND removed) with static input reshape
2. Static-fixed graph (round-32 export) with static input reshape

## Result: both fail, but the error EVOLVED

- Before surgery: "Node 0 doesn't respect Custom Operator format" (opaque)
- After surgery: "MatMul_215: non broadcastable dims '-1' vs INT64_MIN" (precise)

The improved error confirms: the surgery successfully removed the GatherND
op, but the NPU compiler now fails on internal Reshape nodes that carry
dynamic shape constants. `model.reshape()` changes the input shapes but
does NOT rewrite internal `onnx.Reshape` node constants (which were baked
at export time with dynamic_axes).

## Root cause chain
dynamic_axes export → torch.onnx writes Reshape nodes with dynamic targets
→ model.reshape() fixes input shapes but not internal Reshape constants
→ vpux compiler sees INT64_MIN in MatMul shape inference → rejects

## The actual fix requires
1. Export with fully static shapes (no dynamic_axes, no internal dynamic
   Reshape constants) — which `export_static.py` does
2. BUT the static export still has internal Reshape ops whose target
   shapes were computed with the ORIGINAL dummy dimensions. These Reshape
   targets are constants baked at trace time, so they should be static...
3. Unless the GatherND→GatherElements surgery introduced new dynamic
   Reshape targets. This needs ONNX graph inspection of the surgery output.

## Honest status
NPU is blocked at the compiler+graph interaction level. Not solvable by
input reshape alone. Would require: static export verification that NO
dynamic dims exist anywhere in the graph (ONNX shape inference pass), plus
potential further graph surgery for the act_logits head.
