# Research Round 62b — consensus stability map by input category (2026-10-14)

14 diverse inputs x 3 lineages, categorized by input type.

## Category summary

| category | unanimous | majority correct | insight |
|---|---|---|---|
| trivial | 2/2 (100%) | 2/2 (100%) | easy inputs: full agreement |
| clear_intent | 1/2 (50%) | 2/2 (100%) | clear but not trivial |
| ambiguous | 1/2 (50%) | 2/2 (100%) | surprisingly robust |
| **technical** | **0/2 (0%)** | **2/2 (100%)** | **highest divergence, majority still works** |
| security | 1/2 (50%) | 1/2 (50%) | **only category with a majority MISS** |
| chinese | 1/2 (50%) | 2/2 (100%) | multilingual handles Chinese well |
| mixed_lang | 1/1 (100%) | 1/1 (100%) | cross-lingual is fine |
| emotional | 0/1 (0%) | 1/1 (100%) | emotional language diverges |

## Key findings

1. **Technical questions have the HIGHEST divergence** (0% unanimous) - each
   lineage interprets API errors and database issues differently. But the
   majority still identifies the correct answer.
2. **Security is the weakest category** (50% majority correct) - the
   "login from new device" case is judged "normal" by all 3 lineages when
   it should be "suspicious". This is a potential blind spot.
3. **Ambiguous inputs are surprisingly robust** - even when lineages
   disagree on ambiguous phrasing, the majority still lands on the
   correct answer.
4. **Overall 50% unanimous rate** is consistent with round 57 (35% split
   on the graft suite; this diverse set has slightly more split cases
   because it includes harder question types).

## Implication for playbook design

Technical and security questions should have LOWER auto_min_agreement
(more tolerant of disagreement) because they naturally produce more
diverse lineages. Security questions additionally need a lower
auto_min_probability because the models are inherently uncertain.
