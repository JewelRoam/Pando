# Research Round 174 — The live voter's confidence scale, fitted from the wire and scoped before it ships

Date: 2026-10-17

The checkpoint that casts the deciding vote on the island is not the one that
has a training harness here. `laya-en` is an int8 ONNX file on a Raspberry Pi 5
(571 MB, ~199 ms/decision); it is reachable only over LAN, and the root's gate
reads its probability. Until tonight the system had exactly two things to say
about that scale: `uncalibrated_checkpoints: ["laya-en"]`, which was true, and
nothing that could make it false.

`tools/fit_stem_temperature.py` closes that by asking the *running* member the
questions the suites already have labels for. One parameter, fitted by NLL,
on states checked to be disjoint from the checkpoint's 827 training rows
(0/720 overlap, by both state string and task id).

| split | n | acc | mean_p raw | ECE raw | ECE calibrated |
|---|---:|---:|---:|---:|---:|
| fit (`heldout`,2,3) | 720 | 0.6819 | 0.8179 | 0.1377 | 0.0714 |
| holdout (4, 6) | 480 | 0.7417 | 0.8352 | 0.0936 | 0.0461 |
| shift: split F (`general`) | 120 | 0.6833 | 0.6663 | 0.0396 | **0.0842** |
| shift: `distill_ft5_holdout` | 91 | 0.8022 | 0.8576 | 0.0851 | 0.0581 |

`T* = 2.6661`. The member is overconfident by about 14 points of ECE and
roughly halves that on data it has not seen.

**Two things this is not.** First, temperature scaling fits *confidence*, not
accuracy — accuracy is invariant under it. A calibrated wrong member is a wrong
member that knows how unsure to be; nothing here moves a decision. Second, one
temperature is one curve. On split F the raw member is already well calibrated
(0.0396) and this table makes it *worse* (0.0842). An earlier draft reported
“shift” as one averaged number over both shift suites, which hid exactly that.
The tool now reports per suite and writes `out_of_scope_domains` into the
artifact, so the table cannot be read as “laya-en is calibrated” — only as
“calibrated on the fitted domains”.

**What it does to the live gate: nothing, and that is the useful part.** On the
2026-10-17 live group decision the member voted `p = 0.5379`; this table maps
that to 0.5142 — *further* from the root's `auto_min_probability = 0.6`, not
closer. Calibration removes the `uncalibrated_checkpoints` blocker; it does not
open the auto tier. Necessary, not sufficient.

## Artifacts

- `assets/calibration/laya-en.json` (fitted on the pi5 stem; declares its
  fitted and out-of-scope domains)
- `tools/fit_stem_temperature.py` (harvest + NLL fit + per-suite reporting;
  refuses to overwrite an existing table)
- `assets/heldout*_test.jsonl`, `rollouts/distill_ft5_holdout.jsonl` (label
  source — the project's own generation pipeline)

## 反思与质疑

- **统计功效**：fit n=720，accuracy 1 SE ≈ 1.74pp；ECE 从 0.1377 降到 0.0714，
  差 ~6.6pp，远超噪声，这一条是真的。但它是"尺度"的结论，不是能力的结论：
  精度差异（fit 0.6819 vs holdout 0.7417）也在 1 SE 附近，不构成任何提升声明。
  240 行套件的 1 SE ≈ 2.7pp、120 行 ≈ 4.2pp——split F 上 ECE 从 0.0396 恶化到
  0.0842，n=120，这个"恶化"本身也只值 ~1 SE，只能说"没有证据表明它在 F 上有效"。
- **缺对照**：本任务完全没有触及能证伪项目立论的那条对照——"等内存预算下
  多台小模型 vs 一台大模型"。校准做的是让一个已有成员的概率刻度可解释，
  它对"群体是否比单机强"这个问题一个字都不回答。
- **外部锚点**：**内部自洽、外部未锚定**。标签来自 `assets/heldout*.jsonl`，
  这些套件出自项目自身的生成管线；温度是在同一条管线的分布上拟合的，
  又在同一条管线的分布上评估。整个表描述的是"成员与自家标签的一致性"，
  不是"成员与真实世界的校准"。
- **运维代价**：一次拟合 = 1411 次串行决策 ≈ 4–5 分钟（~460ms/次），且
  stem URL 是临时端口，重启即失效，必须从 `/nodes` 现读。这张表不是免费的，
  而且它随任何一次 stem 重启都可能过期；我把它记进分母，不当作零成本。
- **可证伪的替代解释**：也可以说 2.6661 只是"这个 int8 量化版本在这批
  提示上的温度"，而不是 laya-en 的性质——换量化精度、换提示分布，它会漂。
  如果哪天把同一个 checkpoint 用不同量化导出，温度显著不同，就说明这是
  量化/采样伪影，而不是模型置信度问题。目前没有任何对照能排除这一点。
