# Research Round 154 — Counting opinions, and letting the advisor see them: the system outgrows its best member

Date: 2026-10-16

## Part 1 — the member gets its temperature

`ft-v3`'s confidences are saturated: 228 of its 240 recorded votes on split C
are exactly 1.0, so the gate's probability channel has been inert for the
strongest member the fleet has, and every live row it voted on carried
`uncalibrated_checkpoints: [ft-v3]`.

`tools/calibrated_gate_check.py` fits one temperature by NLL on the recorded
votes of split C — a split the fine-tune never trained on and that is not the
evaluator — and applies it exactly where the live root applies calibration:
to every vote before aggregation, and to the combiner's inputs. The fit:

| | before (T=1) | after (T=6.56) |
|---|---:|---:|
| NLL on C | 300.076 | **71.084** |
| ECE on C (5 bins) | 0.0909 | **0.0127** |

The table ships as `assets/calibration/ft-v3.json`. On split D the system
effect of the member's calibration, measured offline through the same code
path the root uses:

| configuration (240 rows of D) | gate full | auto | auto acc | decided |
|---|---:|---:|---:|---:|
| trio, raw | 0.7583 | 209 | 0.8278 | 0.8125 |
| trio, shipped tables | 0.7583 | 182 | 0.8846 | 0.8333 |
| trio + ft-v3, raw | 0.8208 | 194 | 0.8866 | 0.8667 |
| trio + ft-v3, calibrated | 0.8250 | 188 | **0.9149** | **0.8792** |

Two honest notes. The trio's *own* shipped tables already lift the offline
system (0.8125 -> 0.8333), which the round-153 offline numbers had not
included. And the member's calibration buys +1.25 points of decided accuracy
in this configuration but only one row (in the other direction) in the
all-accelerator membership below — its real value is trust: ECE drops 7x and
the uncalibrated flag disappears, which is what an acting policy like
`AutonomyLoop` reads.

## Part 2 — the live fleet's ceiling was the replica, not the member

The round-153 live fleet (iGPU english, NPU english, RTX 3070 ft-v3, quorum
3/3) decided 0.8292. Replaying its recorded votes exposed why: its aggregate
`full` is 0.7292 — exactly the english lineage's solo score. The two english
stems vote byte-identically, so they are a permanent 2-of-3 majority and the
distinct member can never change an answer; calibrating that member changes
nothing (0.8292 either way). **Replicas do not merely buy nothing (rounds
121-146); they actively dilute a better distinct member in stem-majority.**

The fix shipped in round 121 and measured offline then — count the quorum
over opinions (`--lineage-quorum`) — had never been run against a fleet
where it mattered. Offline, on D, the same three devices:

| english x2 + ft-v3 | full | auto | auto acc | decided |
|---|---:|---:|---:|---:|
| live membership, stems counted (round 153) | 0.7292 | 198 | 0.8485 | 0.8292 |
| lineage-counted, raw | 0.9417 | 160 | **1.0000** | 0.9792 |
| lineage-counted, calibrated | 0.9417 | 159 | **1.0000** | 0.9750 |

Cross-checked on split C (where the temperature was fitted, in-sample for T
only): live membership 0.8458, lineage-counted 0.9208/0.9250. Both splits
agree on the direction and rough size of the lift.

## Part 3 — the advisor must see what the quorum counted

The first live lineage-counted run decided **0.9000**, not the predicted
0.9750 — auto 159/240 at 1.0000, but the advisor suggested only 0.7037 on the
81 declined rows. The offline mirror reproduced 0.9000 exactly and localized
the gap: rootd was handing the *combiner* all three stem votes
(english, english, ft-v3), while the quorum had counted opinions. The combiner
was fitted on distinct memberships; a duplicated lineage swamps it exactly on
the rows where the two opinions disagree — which are the rows it is for.

Feeding the advisor the collapsed opinion set, measured on the declined rows:

| declined rows | advisor acc, sees stems | advisor acc, sees opinions |
|---|---:|---:|
| split D (81 rows) | 0.704 | **0.926** |
| split C (73 rows) | 0.685 | **0.904** |

The change is three lines in `pandosi/rootd.py` (advice =
`collapse_lineages(votes, blocs)` when the quorum collapses; smoke suite
19/19 after). The live re-run, same three devices, zero CPU inference:

| live run on split D | round 153 | round 154a (counted, old advice) | round 154b (now) |
|---|---:|---:|---:|
| auto-executed | 200 @ 0.8500 | 159 @ **1.0000** | 159 @ **1.0000** |
| suggestions on declined | 40 @ 0.7250 | 81 @ 0.7037 | 81 @ **0.9259** |
| decided | 0.8292 | 0.9000 | **0.9750** |
| wall / throughput | 29.8 s / 8.0 rows/s | 29.8 s / 8.0 rows/s | 30.9 s / 7.8 rows/s |
| host CPU / left free | 21% used / 79% free | 21% / 79% | 23% / **77% free** |
| fleet + root CPU per row | 143.9 ms | 143.9 ms | 145.5 ms |

Prediction from the offline mirror was 0.9750 with advisor accuracy 0.926;
the live run delivered 0.9750 with 0.9259 — the first time in this project
that an offline prediction was written down before a live deployment and
then reproduced to the digit.

## What this establishes

**The system now exceeds its best member.** `ft-v3` alone decides 0.9417 on
split D; the three-device system, with opinions counted and both the gate and
the advisor reading them, decides **0.9750**, and every one of the 159
auto-executed rows is correct. The "admission is a floor, not a lift" tension
of round 153 was not a property of the member; it was the fleet's quorum
arithmetic.

**Elastic fleets that grow by replication must count opinions — and every
consumer of the votes must see the same set.** Both halves of that sentence
were measured to matter: counting alone recovered +7.1 points over the live
membership (0.9000), and letting the advisor see the counted set recovered
the remaining +7.5.

**Honest edges.** The iGPU's cost-aware ranking was distorted by its compile
window (it served only 20 rows and its window-CPU reads 676 ms/decision
against a 56.5 ms self-report steady state); the cost bands, not the silicon,
kept it mostly idle. And on D, withholding the member's calibration would
have decided one more row (0.9792 raw vs 0.9750 calibrated) — calibration is
shipped for ECE and policy, not for that one row; C measures the opposite
sign. One row on 240 is noise either way.
