# Research Round 83 — Spore reproduction DAG validation

Date: 2026-10-14

## Change

Spore lineage validation now accepts a single-parent, branching DAG rather
than only a linear chain:

```text
origin
  |- B -> D
  |- C -> E
```

`validate_lineage_graph()` checks:

- exactly one generation-0 root (when required);
- every non-root has a parent;
- parent generation is exactly one less than child generation;
- duplicate manifest hashes are rejected;
- optional single-chain mode rejects forks;
- optional maximum generation is enforced.

## Result

The DAG check produced:

```text
manifests: 5
roots: 1
max generation: 2
forks: 1
```

The following invalid graphs were rejected:

- removing the root so children reference a missing parent;
- changing a child generation without changing its parent;
- inserting a second generation-0 root;
- running fork nodes in single-chain mode.

## Node identity

An initial DAG build exposed a real identity issue: two children with the
same payload, metadata, parent, and signing key produce the same manifest
hash and cannot be distinguished. The valid DAG therefore includes an
explicit node identity in metadata.

## Limitations

- All nodes still use one signing key.
- Multi-parent merge semantics are not defined.
- A local verifier can detect a missing parent but cannot prove that the
  parent ever existed outside its own history.

These are the remaining requirements for a fully decentralized
reproduction DAG.
