# Research Round 75 — Multi-step RLCD training from real lineages

Date: 2026-10-14

## Data extraction

The 205 recorded rollouts contained 10 usable contrast pairs after
excluding unanimous/tied decisions and cases with fewer than three votes.

Rows came from two real sources:

- the earlier onnx/GPU/NPU lineage splits;
- the new English/multilingual/typed-decision HTTP lineage check.

## GPU run

Command:

```bash
python tools/export_rlcd.py \
  --rollouts rollouts/rollouts.jsonl \
  --out rollouts/train_rlcd_all.jsonl

.venv-cuda/Scripts/python tools/rlcd_cuda_train.py \
  --data rollouts/train_rlcd_all.jsonl \
  --output-dir artifacts/rlcd-cuda-v2 --json
```

## Decision stability

The original and trained checkpoint were evaluated on the 14-task English
graft slice:

| metric | original | trained |
|---|---:|---:|
| accuracy | 0.7857 | 0.7857 |
| label agreement | - | 14/14 |
| max confidence delta | - | **0.1820** |

No labels changed. Confidence moved most on the refund and safety-adjacent
cases, which is consistent with the contrast rows.

## Calibration warning

There was only one calibration item, so temperature fitting was correctly
skipped:

```text
choice: not fitted: 1 calibration items, fewer than 10
```

The in-sample calibration slice improved loss and Brier score, but that is
not held-out evidence.

## Data-schema problem

The training set contains multiple `intent` definitions with different
criteria. `laya.train` warned:

```text
Conflicting schema detected for question 'intent' across rows;
keeping first seen definition.
```

This means some later rows were interpreted under the first row's intent
option set. The next dataset version must normalize question schemas before
training; otherwise contrast pairs can train against the wrong label space.

## Interpretation

The evolution loop now has a real multi-step GPU path:

```text
live heterogeneous HTTP rollouts
  -> contrast-pair export
  -> CUDA RLCD training
  -> checkpoint reload
  -> decision comparison
```

The current result proves pipeline execution and numerical stability
(14/14 labels unchanged), not generalization. The next useful signal is
whether a larger, schema-normalized dataset starts fixing wrong labels on
held-out tasks.
